# Change the Context

**Phase:** Ideation (Part 1 — Fanning Out / Round Out)
**Status:** Essential — flagged "the one ideation activity to do if you only do one" (Part 1 slide 40, Menu slide 35).

**Source — training narrative:** Design Part 1 deck slides 41–46 (intro + activity-card metadata); slides 58–61 (live practice example with verbatim instruction text).
**Source — canonical activity card:** Menu of Design Activities slide 35.
**Source assets (ideas42 internal):** Starter Deck (sample); Input Sheet Template (sample). Both linked from the activity card on Menu slide 35. Pending pull into `04_Assets/design-activities/`.
**Design Guide point person:** Samantha Hammer.
**Function (per Menu):** Generate Ideas. Good for remote teams. Not good for co-design.
**Effort (per Menu):** 1–3 hours prep; 1–2 hours individual session; ~1.5 hours optional group session. 1–5 designers.

## Purpose

A generation activity that breaks the team out of their default frame by re-anchoring the problem in the **contextual features and behavioral barriers** identified during Diagnose. The Menu defines it tightly: _"Designers are given a list of contextual features that relate to identified barriers. They individually brainstorm ways to counter those contextual features, then pool their thoughts."_

The training is explicit that this is **not** generic context-switching ("imagine the 1990s version of the problem"). It's specifically anchored to ideas42's diagnosis output — that anchor is what makes it the mandatory ideation activity per Part 1 slide 41 speaker notes: _"This activity is crucial to our theory of change at ideas42, which is why it's mandatory. If we don't start with our diagnosis, we're just like any other design firm."_

## When to use it

- **Always, as the first-pass ideation activity** — Menu slide 35 explicitly: _"Change the Context is particularly good as a kick-off activity for (1) Fan Out."_
- **Also good in Round Out** (Menu slide 35) — _"if there are new contextual features, or ones that have not been given enough creative attention."_
- After it, run 1–3 additional ideation activities (Forced Fitting, Trade, Creative Matrix, Telephone) to round out gaps surfaced by Categories.

## How it differs from neighbors

- vs **Forced Fitting**: Forced Fitting forces a connection between two unrelated arrays (e.g., behavioral interventions × channels, or "Picture This" — generate ideas based on an arbitrary image). Change the Context anchors to the *team's own* diagnosis features.
- vs **Trade**: Trade hands the problem to another industry/role. A specific kind of context change, but external; Change the Context is internal to the diagnosis.
- vs **Creative Matrix**: Creative Matrix is more structured (axis × axis grid). Change the Context is broader/looser.
- vs **Telephone**: Telephone iterates ideas through successive participants. Change the Context generates fresh starting ideas.

- [ ] **Pull the contextual features and behavioral barriers list from the team's Diagnose deliverables** — these are the inputs the activity operates on. Without them, this becomes generic brainstorming and loses what makes Change the Context "the mandatory one."
- [ ] Customize the Starter Deck — once `04_Assets/design-activities/change-the-context-Starter-Deck.pptx` is pulled from the Box folder, swap in the design challenge and the contextual-feature list. Until then, fall back to the Input Sheet Template (a spreadsheet with one tab per participant; a column per contextual feature; the participant fills the column with ideas).
- [ ] Decide individual-only vs individual + group session (Menu allows both; default is individual-first to maximize idea volume per Principle #2 "Individual Thinking" from Part 1 slide 32).
- [ ] Block 1–2 hours for individual session; +1.5 hours if group session follows.
- [ ] Confirm whether partners join (Menu marks this **not good for co-design** — partners typically don't have the diagnosis fluency the activity assumes).

## In-session timing

- 5 min: framing + recap of design challenge + read-through of contextual features / barriers list
- 1–2 hours: silent individual generation in the input sheet — one column per contextual feature, generate ideas to "flip" each contextual feature so it's no longer a barrier
- (If group session) 30 min: pool ideas, dedupe, identify themes
- (If group session) 30 min: spot gaps — which contextual features got few ideas? Tag for round-2 ideation
- 10 min: capture, hand off to Categories (first consolidation)

## Prompt templates

The 10-min training-practice version (Part 1 slide 59), verbatim:

> **Change the Context (10 min) — Instructions:**
> _List ideas to solve for the behavioral barriers and contextual features listed in the sheet._

The full design-phase version, parameterized for use in a real session:

> **Change the Context — for {design-challenge}**
> _On the input sheet, you'll see one column per **contextual feature** and **behavioral barrier** identified during Diagnose. Working individually, generate ideas in each column for how the design could **counter** that contextual feature or **flip** that barrier so it stops getting in the way of {target-behavior}._
> _Aim for quantity over quality — Principle #1. The wackier the better at this stage. We'll consolidate later._
> _If you get stuck on a column, skip it. We'll come back as a group._

Per-column micro-prompt (insert at the top of each input-sheet column):

> _Contextual feature: {feature}. Behavioral barrier: {barrier}._
> _Ideas for how the design could change this:_

## Common pitfalls

- Running it without the Diagnose-stage contextual-features list. The activity stops being "Change the Context" and becomes generic brainstorming — losing exactly the thing that makes it ideas42's mandatory ideation activity.
- Skipping the silent individual generation step. Group-only generation under-produces because it triggers anchoring (Part 1 Principle #2).
- Letting "quantity vs quality" trade-off creep in early. Aim for quantity here. Consolidation is what separates wheat from chaff.
- Treating the activity as a one-shot. Per Menu slide 35, it's also useful in **Round Out** (third sub-stage) when new contextual features surface or earlier features got under-attended.

## Debrief questions (training-standard, Part 1 slide 64)

- How did it go?
- What came up in your break-out room discussion?
- Would you feel comfortable using this activity on a project?

Project-specific debrief additions:

- Which contextual feature generated the most ideas? The fewest?
- Which ideas surprise the team — and would not have surfaced under default framing?
- Where are the gaps? (This sets up which other ideation activity to run next: Trade if a context-shift is needed; Forced Fitting if you need to break out of conventional framing further; Creative Matrix if the gap is along a structured dimension.)

## Output handoff

Raw idea output (typically 50–200 ideas after individual session, more after a group session) goes to **Categories** for first-consolidation clustering. Don't try to deduplicate or quality-filter inside this activity — that's Categories' job.
