# Live Facilitation Aids

This reference owns the **mid-session** route — when the user pulls the skill up while actively running an activity, or 15 minutes before, and needs in-the-moment help.

## Mode of engagement

Live use is fundamentally different from planning use. The user does **not** want a comprehensive walkthrough — they want fast, scannable answers to "what's the next step / what do I say / how do I keep this from going off the rails."

Three live-use shapes:

1. **Pre-session prep (T-15 min to T-1 day)** — "I'm running Categories tomorrow with the team, prep me."
2. **In-session reference (T+0)** — "We're in Dot Voting and people are stuck on what counts as 'feasible' — what do I say?"
3. **Post-session debrief (T+0 to T+1 day)** — "Activity is done, here's what came out, what do I do with it?"

## Behavior rules per shape

### Pre-session prep

- Surface the activity's prep checklist (from `references/activities/{slug}.md`) with concrete asks: materials, slides, who briefs partners, time blocks.
- Customize the prompt templates to the user's design challenge, if known.
- Flag the 1–2 most common pitfalls for that activity.
- Offer to generate a Starter Deck if the user wants one (route to deck-production flow).
- Don't dump the full reference. The user is short on time.

### In-session reference

- **Lead with the answer in one sentence.** No preamble, no "great question," no recap of what the activity is. The user is in front of a team and waiting.
- Then offer one optional follow-up sentence with rationale.
- Use telegraphic phrasing — "Say: 'Let's silent-vote first, then discuss.'" Not paragraphs.
- If the question implies a known pitfall, name the pitfall + the move that gets them past it.

### Post-session debrief

- Ask what came out (idea count, surprises, friction, partner reactions).
- Apply the activity's debrief questions from its reference file.
- Recommend the next activity in the sequence — and flag if the output suggests deviating (e.g., "your Categories has a thin cluster, you may need more ideation before consolidating").

## Cross-activity pacing principles

- **Silent first, then discuss.** Almost every activity in the menu benefits from silent generation/voting/sorting before group discussion. Anchoring effects are real.
- **Time-box aggressively.** Set timers visibly. Activities run long because nobody enforces the box.
- **Break at 50–75 min.** Cognitive fatigue tanks idea quality. The Part 1/2/3 trainings all explicitly include a 5-minute break in the middle.
- **Recap → Activity → Capture → Hand-off.** Every session has these four beats. Skipping the capture step (snapshot, file the output, name it clearly) is a common failure.
- **Don't apologize for the activity.** "I know this is going to feel weird, but..." primes the team to perform. State the activity matter-of-factly and start.

## Cross-activity debrief questions (always ask)

1. What surprised you?
2. Where did the conversation get stuck — and what was underneath the stuckness?
3. Whose voice did we miss in this session?
4. What does this output force us to do next?

## Common cross-activity pitfalls

- **Mid-activity scope creep.** Someone tries to redefine the design challenge mid-ideation. Defer it to a parking lot, return to the activity.
- **One person dominating.** Use silent rounds, name-call participation, or split into smaller groups.
- **No handoff.** Activity ends, output sits in a Miro board nobody returns to. Close every activity with explicit "where does this output live, who owns it next."
- **Skipping the Equity Premortem revisit.** Especially in Sprint mode. Don't.
- **Treating output as decisions.** Activity outputs are inputs to decisions, not decisions themselves. Name the next decision-making step.

## When the user is stuck mid-session and asks "should we abort?"

Default: don't abort. Activities feel worse mid-flow than they look in retrospect. Suggest:

1. Take the 5-min break early.
2. Switch to silent mode if the discussion is dominated.
3. Cut scope (drop a sub-activity, narrow the prompt) rather than abort.
4. If genuinely broken (wrong prompt, wrong mix of people, wrong upstream input), name it openly with the team and pivot to a planning conversation about what to run instead.

## Output handoff

Live facilitation aids don't typically produce artifacts in-session — the artifact is the activity output (idea list, voting results, sketches). Post-session, the user often wants help **synthesizing** what came out — route to `synthesis-flows.md`.
