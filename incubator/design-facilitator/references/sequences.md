# Activity Sequences — Plan the Design Phase

**Source:** Menu of Design Activities slides 22–30; Simple Instructions for design.docx.

This reference owns the **plan-the-sequence** route. Read this when the user is asking what activities to run for an upcoming design phase.

## Inputs needed before recommending a sequence

Before any sequence comes out, the skill must know:

1. **Timeline.** Sprint (~1–2 weeks), Typical (~8–10 weeks), Deep Dive (~10+ weeks), or custom?
2. **Partner involvement.** Highly engaged (joining sessions), somewhat engaged (briefed but not in sessions), or hands-off?
3. **Design challenge** in one sentence — the behavior, the audience, the context.
4. **Prior phase outputs.** Has the team done their Equity Premortem? Diagnose deliverables? (If not, the sequence's Step 0 is "go finish those.")
5. **End-user accessibility.** Can end-users join activities directly (co-design model), or is feedback indirect (Concept Cards, user testing only)?
6. **Team capacity.** How many ideas42 team members can show up? This caps how many activities are feasible.

Ask only what's not already in context. Don't re-ask if uploaded docs cover it.

## The three default sequences

### Sprint — 1–2 weeks (including 1 day of prep)

Source: Menu deck slides 23–24.

The fastest path through the Design phase. Use when timeline is tight and the team accepts lower-fidelity outputs.

| Day | Activity | Notes |
|---|---|---|
| Day 0 | **Step 0 — revisit Equity Premortem** | Non-negotiable, even in Sprint mode |
| Day 1 | **Change the Context** (ideation) | Essential opener |
| Day 1 | **Categories** + **Dot Voting** | First consolidation, same day |
| Day 2 | **Weighted Metrics** | Second consolidation — narrow to 4–6 ideas |
| Day 3 | **Elaboration** | One person per top idea |
| Day 4 | **Design Charrette** + **B-Mapping Lite** | Same session |
| Day 5 | **Assumption Listing** + **User Testing Guides** prep | |
| Days 6–10 | **Prototype + User Testing + Revise** | Compressed loop |

Not enough time for: Forced Fitting, Trade, Creative Matrix, Telephone, multiple ideation rounds, multiple test rounds, partner co-design sessions, MoSCoW (use Dot Voting instead).

### Typical — 8–10 weeks

Source: Menu deck slides 25–26.

The default sequence for most ideas42 design phases. Hits all the essential activities, leaves room for partner engagement and a second test round.

Rough shape (week-level):
- **Week 1:** Step 0 + Change the Context + 1 additional ideation activity (Creative Matrix internally if no partner; Forced Fitting with partner if engaged)
- **Week 2:** Categories + Dot Voting (first consolidation); decide if more ideation needed
- **Week 3:** Get early user input via Concept Cards (Step 2 of Simple Instructions)
- **Week 4:** Weighted Metrics + Down-to-Earth (second consolidation, if needed)
- **Week 5:** Elaboration + Assumption Listing
- **Week 6:** Charrette + B-Mapping Lite + prototype build
- **Week 7:** User testing round 1
- **Week 8:** Revise + user testing round 2 (if needed)
- **Weeks 9–10:** Polish (graphic design, partner approval)

### Deep Dive — 10+ weeks

Source: Menu deck slides 27–28.

For complex projects with multiple user segments, deep partner co-design, or a novel domain. Adds breadth (more ideation activities) and depth (multiple test rounds, more elaborated ideas).

Common additions vs. Typical:
- 3–4 ideation activities instead of 2 (add Trade, Telephone with partners)
- Co-design sessions with partners or end-users (see Menu slides 55–57: Prep for Co-Design / Explore Models / Select Activities)
- Multiple consolidation rounds, possibly with MoSCoW for partner-aligned classification
- 8–10 elaborated ideas (vs. 4–6 in Typical)
- 2–3 user testing rounds with progressive prototype fidelity

## Customization rules

The training (Menu slides 29–32) frames customization as two moves:

1. **Add Time** — slow the cadence between activities so the team can absorb. Useful when: team is junior, partners need lag, ideas need to marinate.
2. **Create White Space** — leave gaps where you don't pre-schedule. Useful when: the right next activity depends on what the prior one yielded (a thin Category cluster might force more ideation).

Other customizations: swap activities for partner-friendliness, run activities in parallel (e.g., internal Charrette + partner Dot Voting), insert a Co-Design model.

## How to recommend (output shape)

When the skill recommends a sequence, the output should include:

1. **Sequence name** (Sprint / Typical / Deep Dive / Custom)
2. **Activity-by-activity list** with one-sentence rationale per activity
3. **Calendar** with prep buffers (don't pretend Day 1 starts at the activity — there's always 1–3 days of prep)
4. **Partner-prep flags** — which activities need partner-side prep and what
5. **Decision points** — places where the sequence branches based on what an upstream activity yielded
6. **What's *not* in the sequence and why** — explicit cuts the team is making by choosing this shape

## Default recommendation rules of thumb

- **Always include** Change the Context (ideation), Categories + Dot Voting (first consolidation), Charrette + B-Mapping Lite (build), User Testing Guides (test).
- **Include if partner-engaged**: Forced Fitting prompts, Telephone, MoSCoW, Concept Cards co-review.
- **Include if timeline allows**: Trade, Creative Matrix, Down-to-Earth, multiple test rounds.
- **Skip in Sprint mode**: Forced Fitting, Trade, Telephone, MoSCoW, multiple ideation rounds.

## Output handoff

The sequence plan typically prompts the user to ask next: "OK, walk me through {first activity}." That triggers the **facilitate** route (`references/activities/{slug}.md`).
