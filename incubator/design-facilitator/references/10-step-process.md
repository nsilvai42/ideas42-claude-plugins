# 10-Step DDD(TS) Design Process

**Source:** Simple instructions for design.docx.

The standard ideas42 design phase, end-to-end. Use this reference when the user asks a question that's *not* about a specific activity but about where they are in the bigger flow, or when they reference a step name (Elaborate, Polish, etc.) the activity references don't cover.

Three of these steps were added to the 2020 Design Redesign:
- **Elaborate** — to ensure ideas are clear enough for prototyping
- **List assumptions** — moved earlier (was inside User Testing Guides) so it can shape what gets prototyped
- **Get early user input** — added to make the process more collaborative + equitable; gives end users decision-making weight earlier

## Step 0 — Revisit Equity Premortem

**Non-negotiable.** Refresh the team on pitfalls and solutions surfaced in the Equity Premortem related to the design phase. Skipping this is a known failure mode. Even Sprint sequences include it.

## Step 1 — Ideate

1. Run **Change the Context** as the opener (default).
2. Consolidate, clean, organize the output.
3. Choose 1–3 *additional* ideation activities to fill gaps:
   - Default after Change the Context: **Creative Matrix** (internal), **Forced Fitting** prompts (with partners), then **Telephone** (with or without partners).
   - Choice depends on (1) gaps in Change the Context output, (2) timeline, (3) partner availability.
4. Prep the additional 1–3 activities.
5. Run them, consolidating between each as time allows.
6. Final consolidate to ~20–50 unique ideas.

→ See [activities/change-the-context.md](activities/change-the-context.md), [synthesis-flows.md](synthesis-flows.md).

## Step 2 — Get early user input

A new step. Pick a handful of ideas, make a simple **Concept Card** for each, get user feedback before sinking elaboration time into bad ideas. Reduces wasted elaboration effort and gives users decision-making weight early.

**Skill behavior:** if user is at this step, point them to the Concept Card resource (TBD — pull from Box) and offer to help draft Concept Cards for shortlist ideas. Concept Cards are usually 1-pagers with: idea name, what it does, who it's for, what it asks the user to do, sketch / mockup.

## Step 3 — Select top ideas

1. Team runs **Weighted Metrics** internally to pick top ~15 ideas.
2. Partners run **Dot Voting** (or Weighted Metrics if they're cooperative + capable).
3. Use combined output to pick top 4–10 ideas.

→ See [synthesis-flows.md](synthesis-flows.md), [activities/dot-voting.md](activities/dot-voting.md).

## Step 4 — Elaborate

1. Delegate the top ideas across the team — one person per idea.
2. Each person runs the **Elaboration Activity** for their idea. (Source template TBD — pull from Box.)
3. Optional pre-step: group **Charrette** sketching for each idea before designating an idea-owner.

The Elaboration Activity produces a 1-pager (or equivalent) per idea: what it is, who it serves, what behavior it changes, how it works, what it looks like.

→ See [activities/design-charrette.md](activities/design-charrette.md).

## Step 5 — List assumptions

Run the **Assumption Listing Activity** for each elaborated idea. (Source template TBD.) Surfaces what the team is *betting* about user behavior, partner capacity, market conditions. Output drives:
- What needs to be tested in user testing
- Which assumptions are load-bearing enough to derail the whole design if wrong

## Step 6 — Prototype

1. Decide what to build, based on the 1-pager + Assumption List.
2. Pen-and-paper sketch first (rough).
3. Get team feedback on the sketch.
4. Build the full prototype:
   - Default tool: **PowerPoint**.
   - Web/app prototypes: **Figma**, Balsamiq, or Snagit.
5. Share with team, get feedback, revise.
6. If time allows, more rounds of internal feedback.

**Tip:** if any concept will need a graphic designer in Polish phase, tell **Mitra Salasel** + fill out **Elise's intake form** now. Don't wait.

## Step 7 — User test

1. Decide sampling + recruitment (which user types, how many, which prototypes per person).
2. **Don't forget partner / stakeholder interviews** — they can answer feasibility questions users can't.
3. Recruit + schedule.
4. Write **User Testing Guides** (interview + observation guides).
5. Optional: run mock interviews internally to refine guides.
6. Conduct interviews + observations.

→ See [activities/user-testing-guides.md](activities/user-testing-guides.md).

## Step 8 — Revise

1. Comb interview / observation notes for:
   - What needs to change about each design
   - New or outstanding questions
2. Make the changes.
3. If outstanding questions remain about the designs themselves, run another user test round.

## Step 9 — Polish

1. Get semi-final partner approval on content.
2. Contract illustrations from a Fiverr freelancer if needed (info sheet on Fiverr illustrations exists — TBD pull from Box).
3. Work with **Elise** on graphic design.
4. For complex programs / services / experiences, produce a multi-format design package (the Simple Instructions doc references the **Pace & Progress** project as an exemplar).

## When this 10-step flow doesn't fit

The Simple Instructions doc explicitly notes that for projects where this flow doesn't work, fall back to the **Menu of Design Activities** — pick activities that match the unusual constraints. The skill should be willing to depart from the 10-step flow when the user explains their case for it.

## Quick-reference — which named activity belongs to which step

| Step | Activity references |
|---|---|
| 0 — Equity Premortem | (no activity — review prior deliverable) |
| 1 — Ideate | Change the Context, Forced Fitting, Trade, Creative Matrix, Telephone |
| 2 — Early user input | Concept Cards (resource, not activity) |
| 3 — Select | Categories, Dot Voting, Weighted Metrics, MoSCoW, Down-to-Earth |
| 4 — Elaborate | Elaboration Activity (template TBD); optionally Charrette |
| 5 — List assumptions | Assumption Listing Activity (template TBD) |
| 6 — Prototype | (no group activity — solo build with team review) |
| 7 — User test | User Testing Guides, B-Mapping Lite (often run before testing to predict friction) |
| 8 — Revise | (no activity — synthesis of test output) |
| 9 — Polish | (no activity — partner approval + graphic design handoff) |
